## Why this matters

`pnpm audit` flags a cluster of advisories reaching the tree through
`better-auth`:

- **seroval** (HIGH ×5: RCE via JSON, prototype pollution, DoS) via
  `apps/expo > better-auth > solid-js > seroval`.
- **h3** (HIGH: SSE injection) — partly via the uploadthing path (handled in
  plan 009) but also reachable through the better-auth/server tooling tree.
- **shell-quote** (CRITICAL: incomplete escaping) in dev tooling.

These are transitive; the lever is bumping `better-auth` (and its sibling
packages) to a release whose dependency ranges pull patched `solid-js`/
`seroval`/`h3`. The catalog pins the versions in one place, so the change is
small, but the blast radius (auth) is large — hence HIGH risk and the mandatory
human sign-in check.

## Steps

### Step 1: Determine compatible target versions

Find the latest stable `better-auth`, `@better-auth/expo`, and
`@better-auth/cli`. They must be mutually compatible — `@better-auth/expo`'s
peer range must accept the chosen `better-auth`. If the latest majors diverge,
pick the highest set that satisfies peers (prefer the newest patch of the
current major if a major bump introduces large breaking changes — note the
tradeoff in your report).

**Verify**: you can state the three target versions and that their peer ranges
agree.

### Step 2: Read the changelog for breaking changes

Before installing, skim the better-auth release notes between `1.6.11` and the
target. Note any breaking changes touching: server `auth` config, plugins,
session/cookie handling, the expo plugin, or the API surface
`packages/auth/src` uses.

**Verify**: you have a list (possibly empty) of breaking changes that affect
this repo's usage.

### Step 3: Bump the catalog and install

Update the three entries in `pnpm-workspace.yaml` `catalog:`. Run
`pnpm install`.

**Verify**: `pnpm install` → exit 0.

### Step 4: Resolve any breaking changes

Run the typechecks (auth, nextjs, expo). Fix only what the upgrade broke,
guided by Step 2's changelog notes, within the in-scope files.

**Verify**: `pnpm -F @sortey/auth typecheck`, `pnpm -F @sortey/nextjs
typecheck`, `pnpm -F @sortey/expo typecheck` → all exit 0.

### Step 5: Confirm advisories cleared + tests

**Verify**:
- `pnpm audit --audit-level high 2>&1 | grep -i seroval` → no HIGH seroval
  entries via the better-auth path (other unrelated advisories may remain).
- `pnpm -F @sortey/api test` → all pass.
