# In-App Journey Logging Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn the existing journey-logging prototype into the reliable, mobile-first production record for the current trip, with equivalent web management and durable offline capture.

**Architecture:** Add a first-class `journey_stop` record linked one-to-one to the existing route segment. Keep `trip_segment` as map/routing infrastructure and `pin` as map presentation, while `journey_stop` supplies recorded-versus-planned identity, idempotency, arrival time, stop kind, note, route status, and creator. Put every multi-row mutation behind a database transaction and expose one shared tRPC contract to Expo and Next.js; Expo adds a persisted outbox that retries the same client-generated stop ID.

**Tech Stack:** TypeScript, Drizzle/PostgreSQL, tRPC, Zod, Vitest, React 19/Next.js, React Native 0.85/Expo SDK 56, TanStack Query, Expo Location/Image Picker/FileSystem, pnpm/Turbo, ForgeGraph.

```ts
export const journeyStopKindEnum = [/* exact values above */] as const;
export const journeyRouteStatusEnum = ["ready", "pending"] as const;

export const journeyStops = pgTable(
  "journey_stop",
  (t) => ({
    id: t.uuid().primaryKey(), // generated by the client for retry safety
    tripId: t.uuid().notNull().references(() => trips.id, { onDelete: "cascade" }),
    segmentId: t.uuid().notNull().references(() => tripSegments.id, { onDelete: "cascade" }),
    kind: t.text().$type<JourneyStopKind>().notNull().default("custom"),
    arrivedAt: t.timestamp({ mode: "date", withTimezone: true }).notNull(),
    note: t.text(),
    routeStatus: t.text().$type<JourneyRouteStatus>().notNull().default("ready"),
    createdByUserId: t.text().notNull().references(() => user.id, { onDelete: "cascade" }),
    createdAt: t.timestamp({ mode: "date", withTimezone: true }).defaultNow().notNull(),
    updatedAt: t.timestamp({ mode: "date", withTimezone: true }).$onUpdateFn(() => sql`now()`),
  }),
  (table) => [
    unique("journey_stop_segment_unique").on(table.segmentId),
    index("journey_stop_trip_arrived_idx").on(table.tripId, table.arrivedAt),
  ],
);
```

Create additive SQL as migration `0011` because the active itinerary work already owns `0010_trip_day_planner.sql`. Update the Drizzle journal without renumbering existing migrations.

## Completion criteria

- The real trip can be recorded without an agent session or database script.
- Mobile and web create and manage the same recorded stops.
- Planned itinerary legs never appear as recorded progress.
- Weak/no connectivity cannot lose or duplicate a mobile stop.
- Stop create/update/reorder/delete cannot leave partial segment/pin/stop state.
- Notes and photos remain attached to the correct recorded stop.
- Production web proof and at least one physical-mobile proof are captured.
- Canonical product, implementation, design, and status docs match the shipped behavior.
