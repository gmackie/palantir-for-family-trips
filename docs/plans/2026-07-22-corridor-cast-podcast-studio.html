Overview

Corridor Cast is a trip-scoped audio layer on the Plan Ribbon / TripTik: the user opens a Podcast Studio for a day or leg, picks episode length and topic tiles (checkboxes grounded in the geography they will actually drive), generates a multi-segment script, then optionally renders speech with ElevenLabs. Playback lives on the ribbon (text + chips) and in Drive mode (mini player).

Product one-liner: “Produce a short, van-aware podcast for this drive — not a generic travel channel.”
Rev 2 (2026-07-23, /office-hours): The incumbents (GuideAlong, Autio, the AI-narrator wave) all GPS-trigger live narration because they lack itinerary knowledge. Sortey's moat is that the ribbon knows tomorrow's drive — so the product model is night-before render → offline morning playback, and audio caching is a P0 requirement, not P2 polish (dogfood corridors are cell dead zones). Premises revised: generation pipeline is P0 and the Studio UI is P1 chrome; scripts are grounded in stored route data + corridor POI search (no CMS, but no ungrounded generation either); play-time TTS is cut from P0 — the offline fallback is the downloaded MP3. Full rationale, cross-model review, and P0 spec: design doc ~/.gstack/projects/gmackie-palantir-for-family-trips/mackieg-detached-b17b8ae-design-20260723-113903.md (approved, 3 adversarial review rounds).

Goals & non-goals

Goals

  • P0: one-tap “Generate tomorrow's cast” (15/30 toggle only)
  • P0: grounded scripts — route data + corridor POIs + day anchors
  • P0: night-before render: script + ElevenLabs audio cached to R2
  • P0: offline web playback (SW cache + Download MP3) — airplane-mode test
  • P0: generation status, retry, per-episode cost visibility
  • P1: Studio UX: length presets, topic tiles, tone; ribbon chips
  • Safe defaults (no autoplay while driving without consent)

Non-goals (P0)

  • Editorial CMS / seed history packs
  • Studio controls beyond the 15/30 length toggle (P1)
  • Native Expo audio — standalone trip build has no expo-av; rebuild mid-trip impractical (post-trip)
  • Play-time TTS fallback — offline fallback is the downloaded MP3
  • Multi-voice radio drama; live radio / streaming marketplace
  • GPS-triggered auto chapter by milepost (P2)

Principles

  • Plan is context, not content. Trip days, legs, highways, overnight names feed the prompt.
  • Text is source of truth; audio is a render of script segments.
  • Generate on user action; cache aggressively; never pre-render a whole trip.
  • Chat-primary still holds: co-pilot can open Studio prefilled or “make a cast for tomorrow.”

4. Topic checkboxes & prompt packing

Selected tile ids become a structured field in the generation request:

CorridorCastGenerateInput {
  tripId: string
  scope: { type: "day" | "leg" | "range"; dayDate?: string; legKey?: string; untilDate?: string }
  lengthPreset: "snack" | "standard" | "long" | "deep" | "custom"
  targetMinutes?: number
  topics: Array<
    "highways" | "towns" | "parks" | "geology" | "van_logistics" |
    "culture" | "food_service" | "wildlife_climate" | "engineering" | "history_deep"
  >
  tone: "command" | "warm" | "kid" | "deadpan"
  mustMention?: string
  voiceId?: string
  speakNow?: boolean
}

Context pack (server-built, not user-edited)

  • Day intent, title, hero, cutIfBehind, overnight
  • Ordered place names / waypoints if known
  • Highway labels on the leg(s)
  • Anchors that day or next (birthday, reservations)
  • Season / month for climate framing

LLM output schema

CorridorCastEpisode {
  id, title, targetMinutes, topics[],
  segments: [{
    id, order, title,
    topics: string[],      // subset
    script: string,        // spoken prose
    approxSeconds: number,
    vanNotes?: string[]    // UI only, not spoken unless tone includes
  }],
  disclaimers: string[]    // e.g. verify gate hours
}

Prompt rules: short sentences; no fabricated hours/fees/closures; prefer landscape + human story + van tips; respect selected topics only; fill length budget without padding fluff.

6. ElevenLabs integration

  • cast.speakSegment({ episodeId, segmentId, voiceId }) → audio URL
  • Cache key: hash(script + voiceId + model)
  • Storage: existing @sortey/storage / R2 object; signed URL to clients
  • Env: ELEVENLABS_API_KEY, ELEVENLABS_VOICE_ID_DEFAULT
  • Failure: fall back to text-only; show toast “script ready, voice unavailable”
